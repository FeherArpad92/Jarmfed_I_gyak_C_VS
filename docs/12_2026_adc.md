## 1. Kiindulási program és logikai jelzők

A kiindulási programban a Timer0 közel 10 ms-os időalapot állít elő. Az ISR 10 ms-os, 100 ms-os, 500 ms-os és 1 s-os feladatjelzőket állít, a `main()` pedig végrehajtja a hozzájuk tartozó feladatokat.

A `TRUE` és `FALSE` jelölések olvashatóbbá teszik a logikai állapotokat:

```c
#define TRUE  1u
#define FALSE 0u
```

Ezek nem új C adattípusok, hanem egyszerű preprocesszor-makrók. A változók továbbra is például `uint8_t` típusúak.

## 2. PB0 nyomógomb kezelése pollinggal

PB0-t bemenetnek állítjuk, és bekapcsoljuk a belső felhúzó ellenállást:

```c
DDRB &= ~(1u << PB0);  // a PB0 bit törlése: bemenet
PORTB |= (1u << PB0);  // belső pull-up bekapcsolása
```

> **Fontos:** a `(0 << PB0)` értéke mindig nulla. Önmagában nem töröl egy bitet egy már beállított regiszterben. Egyetlen bit törléséhez az `&= ~maszk` alakot használjuk.

Pull-up mellett a logika aktív alacsony:

| Gomb állapota | PB0 fizikai szintje | `PINB` megfelelő bitje |
|---|---|---:|
| Felengedve | HIGH | 1 |
| Lenyomva, GND-re kapcsolva | LOW | 0 |

Ha minden 10 ms-os feladatban invertálnánk a kimenetet, amíg a gomb lenyomva van, egyetlen hosszabb nyomás több eseményt okozna. Ezért állapotváltozóval csak a lenyomási élt dolgozzuk fel:

```c
static uint8_t pb0_pushed = FALSE;

if (((PINB & (1u << PB0)) == 0u) && (pb0_pushed == FALSE))
{
    PORTA ^= 0x01u;
    pb0_pushed = TRUE;
}
else if (((PINB & (1u << PB0)) != 0u) && (pb0_pushed == TRUE))
{
    pb0_pushed = FALSE;
}
```

Ez továbbra is **polling**: a CPU a 10 ms-os ciklikus feladatban rendszeresen mintavételezi a bemenetet.

## 3. PD0/INT0 kezelése külső megszakítással

A programban már létezik egy periodikus, belső perifériaeseményből származó ISR:

```c
ISR(TIMER0_COMP_vect)
{
    /* ciklikus feladatok ütemezése */
}
```

Most ettől független megszakításforrást adunk hozzá. A PD0 lábon megjelenő lefutó élt az `INT0` hardver érzékeli, és külön megszakítási vektorhoz irányítja:

```text
PD0 lefutó él -> INT0 hardver -> INT0_vect -> ISR(INT0_vect)
```

### Inicializálás

```c
static void external_interrupt_init(void)
{
    /* ISC01:ISC00 = 10 -> lefutó él */
    EICRA = (EICRA & ~((1u << ISC01) | (1u << ISC00))) |
            (1u << ISC01);

    EIMSK |= (1u << INT0);
}
```

A `sei()` globális engedélyezése közös a Timer0, az INT0 és később az ADC megszakításához. Ettől még minden periféria saját engedélyező bitjét is be kell állítani.

### Egyszerű újraengedélyezési idő

Egy mechanikus gomb lenyomáskor több gyors élt is létrehozhat. Az alábbi egyszerű védelem egy elfogadott esemény után 80 ms-ig nem enged újabbat:

```c
#define PD0_ENABLE_DELAY_MS 80u
volatile uint8_t pd0_reenable_ms = PD0_ENABLE_DELAY_MS;

/* A 10 ms-os feladatban: */
if (pd0_reenable_ms < PD0_ENABLE_DELAY_MS)
    pd0_reenable_ms += 10u;

ISR(INT0_vect)
{
    if (pd0_reenable_ms >= PD0_ENABLE_DELAY_MS)
    {
        PORTA ^= 0xffu;
        pd0_reenable_ms = 0u;
    }
}
```

A számlálót az ISR és a főprogram is eléri, ezért `volatile`. A 8 bites hozzáférés a 8 bites AVR-en atomi, de összetettebb közös állapotnál külön kritikus szakaszra is szükség lehet.

## 4. ADC-elmélet

Az ADC (*Analog-to-Digital Converter*) a bemeneti analóg feszültséget digitális kóddá alakítja.

```text
V_in -> mintavétel -> kvantálás -> digitális kód
```

### Felbontás

Egy `n` bites ADC `2^n` különböző kódot képes előállítani. A 10 bites ADC esetén:

```text
2^10 = 1024 kód, vagyis 0...1023
```

Az eredmény nem maga a feszültség, hanem a bemenet és a referenciafeszültség arányát leíró szám. Oktatási közelítéssel:

```text
ADC_kód ~= (V_in / V_ref) * 1023
V_in    ~= ADC_kód * V_ref / 1023
```

A kvantálási lépés nagyságrendileg:

```text
delta_V ~= V_ref / 1024
```

`V_ref = 5 V` esetén ez körülbelül 4,88 mV. A 1023 és az 1024 használata nem ellentmondás: 1024 különböző kód van 0-tól 1023-ig, a végponti kód-feszültség közelítésben pedig 1023 jelenik meg.

### Mintavétel és kvantálás

- **Mintavétel:** a konverter egy időpillanat környezetében rögzíti a bemenet értékét.
- **Kvantálás:** a folytonos feszültségtartományt véges számú lépcsőre bontja.
- Két nagyon közeli bemeneti feszültség ezért azonos digitális kódot is adhat; ez nem programhiba.

### ADC-órajel

Az ADC belső áramköre csak az adatlapban megadott órajeltartományban biztosítja a kívánt pontosságot. A CPU órajelét ezért külön előosztjuk:

```text
f_ADC = f_CPU / N_ADC
```

A gyakorlaton az `ADPS2:0 = 111` beállítás 128-as osztást választ:

```text
f_ADC = 8 MHz / 128 = 62,5 kHz
```

A gyorsabb ADC-órajel rövidebb konverziót jelenthet, de nem feltétlenül ad megfelelő pontosságot. Mindig az adott mikrovezérlő adatlapja az irányadó.

## 5. ADC-csatorna és vezérlőregiszterek

### ADMUX - referencia és bemeneti multiplexer

A mikrovezérlőnek több analóg bemenete lehet, miközben a konverziós mag közös. A multiplexer választja ki, melyik csatorna kapcsolódjon az ADC-re.

```c
ADMUX = 0x00u;
```

Az AT90CAN128-on ez a gyakorlatban az ADC0 csatornát és a külső AREF referenciaforrást választja. Ez a bitkiosztás nem általánosítható minden AVR-re; más típusnál az adatlap megfelelő táblázatát kell használni.

PF0 az ADC0 analóg bemenet, ezért ebben a gyakorlatban bemenetként hagyjuk:

```c
DDRF &= ~(1u << PF0);
```

### ADCSRA - az ADC vezérlése

```c
ADCSRA = (1u << ADEN)  |
         (1u << ADIE)  |
         (1u << ADPS2) |
         (1u << ADPS1) |
         (1u << ADPS0);
```

| Bit | Jelentés | Szerepe |
|---|---|---|
| `ADEN` | ADC Enable | Az ADC engedélyezése |
| `ADSC` | ADC Start Conversion | Egy konverzió indítása |
| `ADIE` | ADC Interrupt Enable | Konverzióvégi megszakítás engedélyezése |
| `ADPS2:0` | ADC Prescaler Select | Az ADC-órajel előosztása |

Az inicializálás még nem indít mérést. Csak konfigurálja és engedélyezi a perifériát.

## 6. Egy konverzió teljes eseménylánca

A 100 ms-os feladat egyetlen bit beállításával indítja el a mérést:

```c
ADCSRA |= (1u << ADSC);
```

A CPU-nak nem kell blokkoló ciklusban várnia. A konverzió végén az ADC megszakítást kér, és az ISR elmenti a 10 bites eredményt:

```c
volatile uint16_t adc_result = 0u;

ISR(ADC_vect)
{
    adc_result = ADC;
}
```

Az eseménysor:

```text
100 ms-os task -> ADSC=1 -> ADC mér -> konverzió kész
              -> ADC megszakítás -> ADC_vect -> adc_result frissül
```

### Miért `uint16_t`?

A 10 bites eredmény legnagyobb értéke 1023, a `uint8_t` maximuma viszont 255. Az eredmény tárolásához ezért legalább 16 bites változó kell.

### 10 bit megjelenítése 8 bites porton

```c
PORTA = (uint8_t)(adc_result >> 2);
```

A jobbra tolás elhagyja a két legkisebb helyiértékű bitet, így a 10 bites `0...1023` tartományból 8 bites `0...255` tartomány lesz. Például `1023 >> 2 = 255`.

### 16 bites változó és atomitás

Az AT90CAN128 8 bites CPU. Egy 16 bites változó másolása több gépi műveletből állhat, és közben az ADC ISR módosíthatja az értéket. Ezért a főprogram atomi blokkban készít pillanatképet:

```c
#include <util/atomic.h>

uint16_t adc_snapshot;

ATOMIC_BLOCK(ATOMIC_RESTORESTATE)
{
    adc_snapshot = adc_result;
}

PORTA = (uint8_t)(adc_snapshot >> 2);
```

A `volatile` láthatóvá teszi az aszinkron módosítást a fordító számára, de önmagában nem teszi atomivá a 16 bites hozzáférést.

## 7. A 100 ms-os feladat időzítése

Az elkészült program először kiírja a **legutóbb befejezett** mérés pillanatképét, majd elindítja a következő konverziót:

```c
if (timer_task_100ms)
{
    timer_task_100ms = FALSE;

    ATOMIC_BLOCK(ATOMIC_RESTORESTATE)
    {
        adc_snapshot = adc_result;
    }

    PORTA = (uint8_t)(adc_snapshot >> 2);
    ADCSRA |= (1u << ADSC);
    PORTF ^= (1u << PF1);
}
```

Ennek következménye, hogy a PORTA-n mindig a legutóbbi **már elkészült** minta jelenik meg. Induláskor ez az inicializált nulla; az első konverzió eredménye a következő 100 ms-os feladatnál lesz látható.

Ez egy szándékosan nem blokkoló, csővezetékes működés:

```text
t0:          előző eredmény megjelenítése, új mérés indítása
t0 + ~t_ADC: ADC ISR elmenti az új eredményt
t0 + 100 ms: az elkészült eredmény megjelenítése, következő mérés indítása
```
